# M7 V2｜AI-FIRST + BYOK 运维

只适用于已确认Ubuntu虚拟机和已授权隔离MySQL，不触及Windows旧认证库。M6的16表128字段及既有迁移行为不变。

## 当前接入

应用工厂挂载 assistant/api_v2.py；api.py仅为兼容导入。旧providers.py/budget.py保留历史回归兼容，不参与V2 HTTP调用链。全局MI2_LLM_ENABLED、平台Key、M7_PAID_API_APPROVED及旧5/50限额不再控制V2；旧私有文件残留该字段也不会启用或禁用用户模型。

用户在 /movies 的个人模型设置中输入自己的DeepSeek Key、选择Flash或V4 Pro、选择不限调用次数并设置单次输出长度，并明确勾选同意。保存只配置、不调用模型；启用后提交对话默认Agent。模型列表检查为单独显式GET /models；生成测试必须单独勾选确认并点击，正常聊天提交本身也是用户明确调用操作。费用归用户服务商账户，不使用平台Key。

## 密钥与部署约束

Key以AES-GCM密文托管在进程内，主密钥也只在内存；AAD绑定用户和登录会话。30分钟绝对到期，断开/退出登录移除托管，服务重启后必须重连。没有明文数据库、LocalStorage、客户端Cookie、URL或日志Key。Python内存回收不等于取证级擦除；在途Provider持有的短期副本最多保留到取消/超时退出。

当前为单进程、线程式测试服务。多进程/多机必须另行实施可信共享短期Vault及一致性调度，不能把当前内存Vault当成分布式状态源。当前接口明确返回此部署模式。

客户机进程关闭core dump。不要在用户Key连接时采集内存/调试转储或运行态VM快照；若需要恢复点，先断开全部用户Key并正常关机。此前M7 V1快照不含V2，不能当作V2恢复证据。本轮不为报告再次启停VM或生成内存快照。

## Agent与费用

允许的模型地址固定https://api.deepseek.com；禁重定向、环境代理和任意base_url。工具只读：目录检索、详情、本人行为摘要/想看、原算法推荐、2—4片比较。工具参数程序校验，库内ID必须来自本轮证据且当前仍可见；模型原文用于回答，结构化卡片用数据库字段。文字不是逐句真实性证明，始终标AI生成。库外建议没有库内ID和行为按钮；可选MI2_TMDB_READ_TOKEN只用于固定TMDB搜索核验，缺凭据明确未核实，不导入数据库。

按用户最新裁决，不设每日或每轮模型/工具调用次数上限；单批工具请求最多8项，90秒总限、15秒单次网络读取超时；每用户同时一个Agent工作、全进程最多4个。实际Provider派发次数仍按UTC日记账（已派发失败/未知也保留，不假定退款；确定未发送的失败原子撤销调用预留，不算实际调用），默认daily_calls=null表示不限，UI不再设置调用次数配额。API兼容显式可选额度但不会替用户默认启用；输出256—8192 Token。接口输入上限2000字符，原8KB正文限制保留。上下文最近12轮、最多60000字符，不设单对话轮数配额、30分钟闲置过期；显式新条件覆盖旧冲突，最终电影还要再次通过服务端条件校验。

requests保存幂等任务和状态，usage逐次记模型/Token/计费是否确定；派发前持久化。超时/未知/取消不重发；重复request_id只读原状态，正文变化409。过期结果变成无原文幂等墓碑，不删除编号后静默重新收费。已消费Token未知就返回null，金额无可靠账单则未知；无调用才能确认为0。模型工具往返是独立记账的计划调用，不是故障重试。

默认关闭语义结果缓存，用户可选5分钟缓存。键含用户、会话、Key连接代次、模型、提示版本、完整上下文及电影/行为版本；目录截断时不使用。命中重新核对库内字段，当前请求Token为0、原请求用量另列。行为变更使缓存失效。

模型中间文本以SSE草稿流式显示，最终JSON/电影ID验证后才输出卡片。完成状态与对话提交使用同一事务和请求行锁；取消先到时不得提交半轮对话。客户端取消会通知后端并中断显示；已发送的第三方请求不保证撤销收费，未知状态不会伪装为零。

## 数据、检查与恢复

复用原M7辅助Schema的5表JSON空间，不新增DDL、不扩大账户权限。v2数据有version/独立键命名空间；请求触发有界清理仅清理V2过期会话/缓存，并把V2过期响应缩为幂等墓碑。没有常驻定时清理；低流量时过期数据可能保留到下次请求。账本留存审计，不自动清理历史原件。

固定 `sudo -n /usr/local/sbin/mi2-m7-check check` 入口保持不变，低权限执行新的V2真实MySQL+ScriptedAgentProvider测试，不联网、不花费额度。测试中的模拟paid=True仅验证未知计费语义，所有Provider类型仍是Mock。不要把这些记录当成服务商账单。

停用/回退：断开全部Key并停止在途请求，保留MySQL辅助数据；优先停用M7配置并恢复M6主功能，不自动DROP任何Schema。baseline仅为代码追溯，禁止把旧V1助手直接挂回同一份V2计费账本：V1过期清理不识别V2幂等墓碑。若回退代码，必须先关闭M7路由并保留账本，再由负责人审查兼容性。旧V1完整包及V2开工前hash备份保留。

真实DeepSeek联调只有用户本地输入Key并主动操作后才能记为已验证。没有证据时必须标NOT VERIFIED。接口依据2026-11-07官方文档核对：https://api-docs.deepseek.com/guides/tool_calls/ 、https://api-docs.deepseek.com/api/list-models/ 。


## 结构化意图协议（当前）

BYOK 的首个既有模型派发强制使用 plan_movie_turn，返回 intent_update 与同批只读 actions。意图不再以规则解析结果为硬约束；模型先按严格 JSON Schema 提出 set/add/remove/clear 变更，经非强制转换的闭合子集类型校验、跨字段冲突检查和有版本的状态合并后，工具与最终校验共同使用 conditions.py。协议与 Schema 唯一定义在 assistant/structured_intent.py；不另行维护重复 Schema。无新增依赖。

无工具的澄清或闲聊可在计划中直接携带模型 answer，一次派发即可；不虚构库内 ID。一个普通目录查询仍为“计划加工具→最终回答”两次派发，不另开专用理解请求；需要更多工具时沿用原 Agent 往返。每次仍单独记账。结构非法不自动重试，回传澄清；语义不确定/条件冲突不执行目录 actions，也不允许返回选中 ID 或库外建议。accepted 条件在本轮内不可被后续工具调用改写。旧规则会话条件只作带提示的未确认历史，模型结合原话重建，不再硬否决正确候选。

无 Key/传输失败保留保守规则兜底，来源为 LOCAL_RULE，不能伪装成模型确认状态。不确定的离线类型表达返回澄清。缓存区分协议版本，并保存/恢复结构化条件状态；内部状态字段不出现在 HTTP 返回中。服务更新重启会清空短期 Key，需用户自行重新连接。

新增测试入口 m6_checks.test_m7_structured_intent；真实 MySQL 仍通过已有 mi2-m7-check check。测试结构化模型响应为人工指定的合成 fixture，不能证明真实模型任意中文理解质量；本协议没有在此次整改中追加真实付费调用。


## 最终输出加固

优先通过 finish_movie_turn 提交最终答案；这是当前模型派发的终结工具，不再为该工具结果追加生成请求。其 Schema 与兼容的直接 JSON 路径共用 FINAL_SCHEMA，随后均执行同一 ID 证据、可见性、当前条件和权限校验。拒绝重复 JSON 字段、非法 ID 类型、未知字段；不把字符串或对象强制转换成 ID。终结工具不可与其他工具混批，不可跳过首轮意图。

整批工具先校验信封、函数形状与调用 ID 唯一性，再执行。缓存升级为 v5-terminal-schema；只读结果的 completion_protocol 标明 TERMINAL_TOOL、LEGACY_JSON 或 PLAN_ANSWER，供脱敏验真，UI不展示技术字段。failure_details 仅含受控原因码、阶段及字段类型，不含原文/Key。历史两次拒绝的具体原因仍未证实，代码边界加固不冒充历史根因证明。
